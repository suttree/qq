# Code Coach

Code Coach helps you prepare a conversation about a pull request. Run its CLI with `qq`. It returns zero, one or two coaching points, each with code evidence, a reason to discuss it, a question to ask, and a principle to explain.

Each review checks for bugs and regressions first, then reviews style, performance, and other coaching opportunities. Supported bugs take priority in the two-point result.

This is an early prototype. Reviews use the OpenAI API by default. Coaching judgement is still being evaluated. See [the evaluation notes](EVALUATION.md) before relying on its output.

## Get started

The example needs only Python 3.11 or newer with curses. Live PR analysis also needs Git, an authenticated GitHub CLI, and an OpenAI API key in `OPENAI_API_KEY`. API reviews send selected PR evidence to OpenAI and incur usage charges. There are no Python package dependencies. macOS and Linux are supported.

Clone the repository, then run the bundled example. Skip the clone if you already have the checkout.

```sh
git clone https://github.com/suttree/qq.git "$HOME/src/qq"
~/src/qq/qq --example
```

The example contains two coaching points using real excerpts from Commonbound PR #11. It was curated during development to show the intended output, not generated by the local model. It discusses email latency and keeping a saved action when a courtesy notification fails. The footer and Context view identify it as a curated example. It works offline and is included in the package.

## Use qq as a shell shortcut

For **zsh**, add this line to `~/.zshrc`:

```sh
alias qq="$HOME/src/qq/qq"
```

Then reload it:

```sh
source ~/.zshrc
```

For **bash**, add the same alias to `~/.bashrc` and run `source ~/.bashrc`. If your terminal starts a bash login shell and reads `~/.bash_profile` instead, put the alias there and run `source ~/.bash_profile`.

Adjust the path in the alias if you cloned elsewhere. You can now run:

```sh
qq
qq --example
qq https://github.com/suttree/commonground/pull/11 --repo ~/src/commonground
```

With no arguments, `qq` opens the bundled example. Supplying a PR URL starts live analysis.

Alternatively, make `qq` an executable on your PATH. This also works for scripts and shells without aliases:

```sh
mkdir -p "$HOME/.local/bin"
ln -s "$HOME/src/qq/qq" "$HOME/.local/bin/qq"
```

If `~/.local/bin` is not already on your PATH, add `export PATH="$HOME/.local/bin:$PATH"` to your shell's startup file. For zsh and bash, use the files above and reload them. Other shells have their own PATH configuration. Use either the alias or the symlink; you do not need both. The symlink command stops if that path already exists.

The launcher works from any directory without installing the Python package. It resolves source files relative to its own location, including when launched through a symlink.

## Model and interface

The normal `qq PR_URL` command uses the OpenAI Responses API with `gpt-6.1-sol` and strict structured output. Set your API key in the shell before running a live review:

```sh
export OPENAI_API_KEY="your-api-key"
qq https://github.com/suttree/commonground/pull/15 --repo ~/src/commonground
```

Select another API model with `--model NAME` or `QQ_OPENAI_MODEL`. The Context view identifies the provider and model. Saved reviews and failure diagnostics include API call metadata and token usage. QQ reads the key from the environment and does not save it with the review. QQ retries once with a larger output budget when a response hits the output token limit. The retry incurs another API call. Missing credentials, API errors, and other incomplete responses stop the analysis. QQ does not automatically switch providers.

To run entirely local inference, select Ollama explicitly:

```sh
qq https://github.com/suttree/commonground/pull/15 --repo ~/src/commonground --provider ollama
```

The local default is `qwen3.5:9b-coding`. Override it with `--model NAME` or `QQ_MODEL`. The legacy `QQ_MODEL` variable applies only to Ollama, so an existing local setting does not change the OpenAI default. Ollama must be running, and QQ never downloads models. Start it with your usual startup command or run `ollama serve` in another terminal. The default local endpoint is `http://127.0.0.1:11434`; `--endpoint URL` requires `--provider ollama`.

Local requests include the JSON schema in the prompt as well as the API format field, as [Ollama recommends](https://docs.ollama.com/capabilities/structured-outputs). Local sampling defaults follow [Qwen's non-thinking settings](https://huggingface.co/Qwen/Qwen3.5-9B), with a fixed sampling seed. Outputs can still vary between runs, and these settings do not guarantee correct reviews.

The UI opens immediately and shows progress while GitHub and the selected provider respond. Press `q` to close. A submitted model request may continue after the viewer closes.

The UI uses pink for titles and the selected tab, orange for the rationale and assumptions headings, and yellow for principles and cited lines. Diff additions are green and removals are pink. It falls back to basic colours or monochrome when needed.

## Edit the coaching prompt

The main model prompt is in [src/qq/PROMPT.md](src/qq/PROMPT.md). Edit this UTF-8 file to change the coaching instructions. QQ reads it for each new assessment, regardless of the working directory. The file is also included in package installations. A missing or empty prompt stops the assessment with an error.

The PR evidence and JSON output schema are supplied separately. The citation correction and relevance check prompts remain in `src/qq/core.py`.

## Navigation

- `Tab` moves to the next section; `Shift+Tab` moves to the previous one. Both wrap around.
- `f` shows the coaching conversation.
- `e` shows cited code with surrounding lines.
- `d` shows the collected diff.
- `c` shows which files and excerpts the model received.
- `n` and `p` move between points.
- `o` opens the first citation on GitHub. `1`, `2` and `3` open individual citations.
- The Evidence view shows PR line URLs and source URLs at the reviewed commit.
- `j` and `k`, arrow keys, or Page Up and Page Down scroll.
- `q` quits.

PR links open the cited lines in the current PR diff. If the branch has changed since
the assessment, use the source URL to see the reviewed version. Citations outside
the collected diff open the source at the reviewed commit instead. Saved reviews
also get these links when reopened. JSON output includes `evidence_links` in the
same point and citation order as the report. QQ builds URLs from the evidence packet
after validating citations. The model does not supply URLs.

## Evidence and limits

QQ reads GitHub's PR title, description and commit IDs. It compares the head with the merge base and reads tracked source from those commits. It does not check out a branch, edit your repository, run repository code, or post comments.

The local repository's origin must match the PR. Both commits must exist locally. If a commit is missing, fetch it into your checkout before retrying. Automatic fetching and cloning are not implemented yet.

QQ reserves space for related code alongside changed files. It searches the reviewed commit for references to Ruby methods defined on changed lines and for source or test filenames mentioned in the PR description. It centres excerpts on matching references and uses a bounded symbol search when few files match. The Context view shows truncation and file coverage. Use repeated `--context-file path/to/file` arguments to include a caller, shared component or test you know matters.

Every accepted finding quotes an exact supplied file excerpt at its actual line. QQ validates the draft's structure and status, then checks its claims against the supplied source and PR description. Unsupported points can be discarded before quote repair. The raw draft and rejection reasons remain in the assessment.

The review prompt asks for a concrete trigger and consequence for each concern. Both
the draft and the relevance check receive the diff so they can distinguish a new
regression from an unrelated pre-existing issue. They also check claims in comments
and the PR description against the implementation. A stated requirement is not proof
that the code meets it. Missing tests alone do not warrant a point. These instructions
adapt parts of the supplied `code-review` skill while keeping the two-point coaching
format. QQ still assesses the full collected PR evidence on each run.

Retained points must pass exact citation validation. If the model gets indentation or a line number wrong, QQ resolves the quote only when it has one unique match in the supplied file. If a retained citation still fails, QQ asks once for source line ranges and copies the exact text itself. It then checks the claims again against those selected lines before accepting any feedback. The model cannot add new points during these checks.

Unresolved citations in retained points, malformed output, and model failures are errors. They are never silently converted into "no feedback". Failed analyses save a `.failure.json` diagnostic beside the evidence packet, including drafts and any corrections received. The Context view shows the final relevance decisions. The selected model performs these checks and can still make mistakes.

The model can return three outcomes:

- `feedback`, with one or two points.
- `no_feedback`, when the reviewed material does not warrant a coaching conversation.
- `needs_context`, when missing evidence prevents a useful assessment.

No-feedback results are scoped to the supplied material, not a correctness guarantee for the PR.

The default OpenAI provider receives the selected source excerpts, PR metadata, diff, and review prompts. Selecting `--provider ollama` sends inference requests only to the configured localhost endpoint. GitHub receives the metadata request through `gh`. Obvious credential paths and binary files are excluded, but this is not a general secret scanner. The checkout launcher saves evidence and model output in the project's `.qq/` directory, which is ignored by Git. Treat that directory as source code from the reviewed repository.

## Repeat an assessment

Collect evidence without calling a model:

```sh
qq https://github.com/suttree/commonground/pull/11 \
  --repo ~/src/commonground --collect-only > packet.json
```

Analyse the same evidence again, or reopen a saved result:

```sh
qq --packet packet.json --json > review.json
qq --open review.json
```

These replay commands use OpenAI by default. Add `--provider ollama` to `--packet` for a local comparison. The older `scripts/compare_openai.py` helper uses the same API client and remains available for saved-packet comparisons.

`--json` runs without the TUI. `--state-dir PATH` selects where evidence and results are saved. Reopening a result requires neither GitHub access nor a running model.

## Check the prototype

```sh
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

The tests cover abstention, missing context, the two-point limit, invalid citations, source selection at historical commits, preserving uncommitted work, sensitive-path exclusions and terminal text handling.

The first real examples are Commonbound PRs #1 and #11. See [the evaluation notes](EVALUATION.md) for results and replay commands. The useful question is whether you would have wanted the proposed conversation at the time. A plausible-sounding answer or a passing citation check is insufficient.
